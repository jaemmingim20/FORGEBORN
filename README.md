# FORGEBORN

[VS Code용 프로젝트 ZIP 다운로드](https://github.com/jaemmingim20/FORGEBORN/raw/refs/heads/main/releases/FORGEBORN-phase1.zip) · [로컬 실행 안내](START_HERE_KO.md)

중세 판타지 대장장이 시뮬레이터의 **Phase 1 — 기본 3D 월드**. 공식 기획서는 첨부 원문을 보존한 [GDD.md](GDD.md)입니다. 지금은 공간 탐방과 1인칭 이동만 구현하며, 채굴·경제·제작·전투를 미리 실행하지 않습니다.

[Phase 1 완료 보고서](docs/PHASE1.md)에 전체 생성 파일 목록, 구현 내용, 검증 결과와 알려진 제한을 기록했습니다.

## 미리보기에서 바로 실행

```sh
npm run build
```

미리보기와 파일 공유용 실행본은 **`standalone/index.html`**입니다. 게임 코드, Three.js, Rapier WASM, 스타일, 한국어 글꼴을 약 7.7MB의 HTML 하나에 포함합니다. 추가 파일 다운로드가 필요하지 않습니다. 단일 실행본만 갱신하려면 `npm run build:standalone`을 사용합니다.

일반 웹 호스팅에는 `dist/` 전체를 배포합니다. 하위 경로에서도 에셋이 같은 폴더를 기준으로 로드되도록 상대 경로를 사용합니다. 저장소 루트의 `index.html`은 아래 Vite 개발 서버가 처리하는 소스 진입점입니다.

로딩 중에는 현재 준비 단계가 표시됩니다. 첫 스크립트·게임 모듈·WASM 로드가 실패하면 오류 안내와 재시도 버튼을 표시하고, 15초 이상 초기화가 지연되면 기다리거나 다시 시도할 수 있는 안내를 표시합니다.

## 실행

Node.js **22.12 이상**(현재 검증: 24.19.0), npm을 사용합니다.

```sh
cd FORGEBORN
npm ci
npm run dev
```

브라우저에서 Vite 서버를 열고 **대장간에 들어가기**를 누릅니다. PC의 키보드와 마우스, WebGL 2 및 WebAssembly가 필요합니다. 포인터 잠금은 사용자 클릭으로 시작합니다. iframe 안에서는 호스트가 `allow-pointer-lock`을 허용해야 합니다. 글꼴, 재질, 모델은 자체 번들/절차적 생성이며 런타임 CDN·백엔드·API 키가 필요 없습니다.

| 입력    | Phase 1 동작                             |
| ------- | ---------------------------------------- |
| W/A/S/D | 시점 기준 이동, 기본 4.5m/s              |
| 마우스  | 1인칭 시점 회전                          |
| Shift   | 달리기 6.5m/s                            |
| Space   | 지상에서 점프, 공중 연속 점프 금지       |
| G       | 현재 위치가 표시되는 탐방 지도 켜기/끄기 |
| Esc     | 일시정지, 마우스 잠금 해제               |

일시정지 화면에서 감도와 걷기 카메라 움직임을 조절하고 시작 위치로 복귀할 수 있습니다. 창 포커스가 사라지거나 탭이 숨겨지면 멈춥니다. 설정과 방문 기록은 현재 세션에만 유지됩니다. G는 Phase 1 탐방용 추가 키이며 GDD의 M(시장), J(일지), Tab(인벤토리) 등은 이후 단계용으로 남겨둡니다.

## 구현 범위

- 카운터 ↔ 대장간 ↔ 뒷마당 ↔ 훈련장, 뒷마당 ↔ 광산 입구의 연속된 월드
- Rapier 캡슐 캐릭터, 정적 충돌체, 고정 60Hz 물리, 중력·점프·낮은 턱 이동
- 용광로 1개, 모루, 담금질 수조, 조립 작업대, 재료 보관함, 완성품 보관대, 구매 장부, 침대
- 응대 카운터, 빈 손님 대기 공간, 완성품 제출대, 운반 수레
- 허수아비 3개, 방패 표적, 훈련 기록판
- 목조/석조 대장간, 숲·산 실루엣·흙길·돌길·울타리, 그림자, 금속 재질, 용광로/횃불 발광과 조명
- 바라본 설비의 이름·용도·향후 연결 단계 안내. 제작/판매/채굴 입력은 연결하지 않음

광산은 약 10m의 짧은 입구 통로까지만 걸을 수 있고 안쪽은 눈에 보이는 폐쇄벽으로 막힙니다. 500m 광산, 광물, NPC, 무기, 인벤토리, 스태미나, 체력, 경제, 날짜 및 세이브는 미구현입니다. 임시 모델은 모두 코드로 직접 생성했으며 외부 3D 에셋을 사용하지 않았습니다.

## 검사

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

`test:browser`는 실제 Chromium에서 개발 서버 및 빌드한 정적 결과물을 검사합니다. `/usr/bin/chromium`이 있으면 사용하고, 다른 머신은 `npx playwright install chromium`으로 설치하거나 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 경로를 지정합니다. Linux에서 라이브러리가 부족하면 Playwright 공식 설치 안내에 따라 브라우저 런타임 의존성을 준비합니다. 테스트는 1개 워커와 소프트웨어 WebGL로 실행하며, 브라우저 탐방 테스트는 수 분 걸릴 수 있습니다.

실패 시 `test-results/`에 스크린샷과 trace를 남깁니다. 정상 실행 스크린샷도 이 디렉터리에 생성합니다. 테스트 전용 `?debug` 훅은 Vite 개발 모드에서만 동작하며 프로덕션 번들에는 노출되지 않습니다. 구역 왕복 검사는 순간이동 없이 실제 키 입력으로 진행합니다. 설비 충돌 검사에만 개발용 위치 지정 훅을 사용합니다.

## 구조와 확장

[구현 전 구조 설계](docs/ARCHITECTURE.md)에 파일 구조, 모듈 경계, 좌표와 기본값을 기록했습니다. `src/world/data.ts`는 구역/설비의 데이터이며, `ModelFactory`는 설비 외형, `WorldBuilder`는 배치와 충돌체, `WorldManager`는 구역/시선 판별을 담당합니다. 게임 규칙은 렌더러에 두지 않습니다. 다음 개발은 **Phase 2 채굴 시스템**입니다.

Rapier 호환 패키지는 WASM을 포함하므로 물리 청크가 비교적 큽니다. 첫 로드는 네트워크/기기에 따라 오래 걸릴 수 있으며 로딩 화면을 제공합니다. 현재 그래픽은 교체 가능한 절차적 임시 모델이고, 실제 GPU별 성능 최적화와 사운드는 후속 단계 대상입니다.
