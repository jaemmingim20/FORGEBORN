# Phase 2 — 채굴 시스템

## 구현 전 설계

Phase 1 이동·건물·설비를 유지하고 광산 폐쇄벽을 열어 고정 시드의 500m 갱도로 연결한다. 깊이는 입구에서 주 통로를 따라 진행한 거리다. 주 통로와 넓어진 채굴실/기둥 주변 순환 공간을 만든다. 몬스터·제련·제작·경제·날짜·저장은 이번 단계에 구현하지 않는다.

추가 모듈:

- `src/mining/data.ts`: 광물 규칙, 깊이별 분포, 고정 시드 광맥 생성.
- `src/mining/MiningManager.ts`: 렌더링과 독립적인 타격·고갈·수집·도구/쿨다운 규칙.
- `src/inventory/InventoryManager.ts`: 20칸 인벤토리, 원자적 수집, 낡은 곡괭이 장착 상태.
- `src/world/MineBuilder.ts`: 갱도 시각 형상과 충돌체.
- `src/mining/MiningView.ts`: 광맥 모델, 시선 레이, 곡괭이 뷰모델·타격 애니메이션.
- `src/ui/MiningUI.ts`: 인벤토리, 채굴 안내, 깊이/구역과 첫 채굴 목표.
- `tests/mining.test.ts`: 깊이·타격·중복 획득·용량·장착의 핵심 테스트.

공통 이벤트로 UI를 연결한다. Tab은 인벤토리를 열고 물리를 멈추며 포인터를 해제한다. 닫을 때 명시적 사용자 입력으로 잠금을 다시 요청한다. 좌클릭 타격은 애니메이션의 실제 타격 시점에 레이로 다시 판정하여 벽 뒤/먼 광맥을 채굴하지 못한다.

기획서 미정값: 광물 한 스택은 최대 99개, 공격 간격 0.65초, 타격 시점 0.24초, 채굴 사거리 3.5m. 시작 곡괭이는 기본 광물만 채굴하며 은/미스릴에는 상위 도구 안내를 표시한다. 3번 키로 곡괭이를 장착/해제할 수 있다. 내구도와 스태미나는 Phase 6에서 추가한다. 하루 재생성·세이브는 Phase 8이다.

검증은 요청에 따라 긴 전체 월드 왕복을 생략하고 타입·핵심 테스트·빌드·짧은 채굴 브라우저 확인으로 제한한다.

## 완료 내용

- 고정 시드 500m 주 갱도, 넓어진 채굴실, 기둥을 돌아가는 순환 공간, 레일과 갱목, 끝 벽.
- 광맥 71개. 구리/철/석탄은 처음부터, 은은 100m 이후, 미스릴은 250m 이후에 생성한다. 깊어질수록 미스릴 비중이 증가한다.
- 광맥당 매장량 2~5개. 구리/석탄 2회, 철 3회 타격. 은/미스릴은 높은 등급의 도구를 요구한다.
- 낡은 곡괭이 뷰모델·장착/해제·타격 애니메이션. 실제 타격 시점에 3.5m 이내의 가장 가까운 충돌체를 검사한다.
- 고갈된 광맥은 숨기고 충돌체를 제거한다. 채굴 완료는 원자적으로 수집하며 재타격에 의한 중복 지급을 막는다.
- 20칸 인벤토리, 광석당 99개 스택, 용량 부족 시 광맥과 마지막 타격을 보존한다.
- Tab 인벤토리, 마우스 잠금 해제/복귀, 장착 버튼, 채굴 진행과 수집 알림, 깊이 구역 표시, 철광석 운반 목표.
- 지상 지도는 유지하며 깊은 광산 내 플레이어 위치는 입구로 축약한다. 광산에서는 별도 깊이 표시와 레일로 귀환 방향을 안내한다.
- 일반 정적 빌드와 Go Live용 단일 HTML을 모두 갱신한다.

## 파일

추가: `src/mining/data.ts`, `MiningManager.ts`, `MiningView.ts`, `src/inventory/InventoryManager.ts`, `src/world/MineBuilder.ts`, `src/ui/MiningUI.ts`, `mining.css`, `tests/mining.test.ts`, `tests/phase2.spec.ts`.

연결 수정: 게임 매니저/공통 타입/입력/물리 쿼리, 월드 배치/구역 범위, 조명, 기존 HUD, 테스트 설정. 기존 광산 끝 벽 브라우저 검사는 의도적으로 열린 입구가 아니라 새로운 500m 끝 벽을 검사하도록 갱신했다. 해당 긴 기존 검사는 이번에는 실행하지 않았다.

## 짧은 검증 결과

- `npm run typecheck`: 통과.
- `npm test`: 27개 통과. 기존 물리/데이터 17개 + 채굴/인벤토리 10개.
- `npm run build`: 통과. 큰 Rapier WASM 청크의 기존 크기 경고는 유지된다.
- `npm run test:browser -- --project=phase2`: 2개 통과, 약 42초.
- 실제 Chromium에서 철광석 3회 타격·수량 수집·인벤토리·장착 버튼·포인터 복귀·기존 입구 폐쇄 위치 통과·재료 보존을 확인했다.
- Go Live와 동일하게 정적 단일 HTML을 제공하여 게임 시작과 인벤토리 표시를 확인했다.
- 광산/대장간 위치 지정은 개발용 테스트 훅을 사용했다. 요청에 따라 전체 지상 구역 왕복, 500m 전 구간 도보와 전체 브라우저 회귀는 생략했다.
- 검사한 정상 실행의 브라우저 콘솔 오류는 없었다.

## 남은 범위

제련·제작·상위 곡괭이 생산·경제·전투·스태미나/내구도·날짜·다음 날 광맥 재생성·저장은 이후 단계다. 현재 광석과 고갈 상태는 세션에만 유지한다. 원래 시작 곡괭이는 판매/분해 UI를 제공하지 않는다. 초기 광산 구조는 고정 주 통로와 채굴실 중심이며 복잡한 절차적 동굴과 청크 스트리밍/사운드/최종 아트는 후속 개선이다.

다음은 Phase 3의 용광로 상호작용, 광석 차감, 제련 진행과 완료 재료 생성이다.
